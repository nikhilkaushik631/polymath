# Polymath design

A desktop workspace used in both daylight and evening light. Neutral surfaces support a restrained set of workspace colors in light and dark themes; document colors remain independent. Preserve 125% interface scale and narrow editor sidebars.

Use a compact shared top bar with Polymath identity, a Home return button, the active workspace name, and essential controls. Keep a compact divider beside the brand without reserving space for a Home sidebar. Home enters Reader, PDF Tools, Writer, Sheets, Slides, Images and Video without a redundant permanent tab row. Workspace switches keep existing work in memory; a dot beside the current workspace marks unsaved changes. The theme action is a Lucide sun or moon icon with a destination-specific tooltip and accessible name. A gear opens one Settings window for appearance, voice and chosen-folder access.

Home uses locally embedded Inter Regular, Medium and Semibold. Real font weights distinguish a 30-point page title, 19-point section titles, 13.5-point action labels and 11.5–13.5-point supporting text. Keep this typography scoped to Home; each editor retains its document fonts and restores its own interface fonts when activated.

Home has no library rail. Recent files and chosen folders appear as compact source selectors above the main file list, with Add folder beside them. The main header reads Your workspace, with a single high-contrast Open a file action that has a document glyph and a separated keyboard shortcut. When files exist, a short Continue working row appears immediately below the header so recent work is visible without scrolling. A Workspaces heading separates navigation from the searchable full file list below. Keep branding once in the shared top bar. Settings → Appearance holds Reduce motion. Home gives Reader and PDF Tools asymmetric featured surfaces side by side at roomy widths or stacked at smaller widths, then Writer, Sheets, Slides, Images and Video larger colored surfaces in two columns or one column. Original illustrations preview the kind of work each workspace handles, never a user's document or a prefilled template. Compact cards use restrained teal, green, coral and ochre cues; there is no violet. The canvas scrolls vertically.

Document surfaces have a short 180 ms hover/focus lift, a press response and a visible keyboard focus ring. Hit targets never move. No idle animation or entrance sequence. Reduce motion replaces the lift transition with an immediate state change, and the preference is saved. First launch reads the macOS Reduce Motion preference; an explicit Polymath setting takes precedence thereafter.

An empty library has a charcoal onboarding panel with Choose folder, local-storage guidance and a drag-and-drop hint. Hide search and filters until there are files, a selected folder or an active filter. Do not invent recent documents or activity. Populated libraries use full-width keyboard-accessible rows, filename search and type filters. Keyboard focus scrolls file rows and folder entries into view; Reduce motion also disables animated focus scrolling. Empty folders offer Refresh files, keeping the header as the only general Open action. Empty, loading, unavailable and no-match states explain the next action. Folder listings remain bounded and nonrecursive. Truncate long paths and folder names with full values available on hover.

Home's light canvas and document trays are grayscale 250/237. Dark values are 22/35. Primary ink is 25 or 240; secondary ink is 102 or 172. Reader and PDF Tools use deep blue, Writer teal, Sheets green, Slides terracotta, Images amber, and Video coral. Use each color for its workspace indicator, selected controls and primary actions, with softer variants in dark mode. Keep document canvases neutral and preserve contrast for text and focus. Use 7–9 point corners for controls and 12–14 point corners for larger cards and panels. Preserve crisp document pages and spreadsheet grid lines. File-type filters use fully rounded 32-point pills, with a selected state and outlined neutral inactive states. Split filters into two visible rows at narrow widths; keep search below them.

The main icon is an original monochrome folded-aperture mark, with a strong silhouette at Dock sizes. Workspace symbols use consistent geometric forms and a single stroke weight. Asset masters live in assets/icons; generated platform icons are reproducible through packaging/icons.sh. Inter and Lucide assets are reused from Reader with their original licenses. Legacy Manrope source and generation scripts remain in assets/fonts and packaging for provenance, but are no longer embedded by Home. All shipped assets are recorded in ATTRIBUTION.md.

Reader is the first destination for every supported file. Its persistent tab strip switches among PDF, office, source, CSV/TSV, image, audio and video files and closes each independently. A deliberate Edit action opens the original in Writer, Sheets, Slides or Images. Reader shows PDFs with PDF-tool controls hidden, previews office files as locally generated in-memory PDFs, displays CSV/TSV in a scrollable table with resizable columns, and displays source text read-only with line numbers, find and copy. PDF and office-preview reading positions are saved locally per file and restored when reopened. A star in Reader pins the active file to Favorites on Reader's landing page; neither action changes the document. Markdown and plain text share Writer's editor and Save As format choice. PDF Tools is a separate workspace using the same PDF session; its complete catalog is visible by default, with category dividers and vertical scrolling. Reader's mode bar uses tabs that fit within its own height and swaps the wide command search for a search icon when space is tight. This pass follows the installed Impeccable product guidance, UI UX Pro Max interaction/contrast guidance, and shadcn icon conventions. The existing Rust/egui architecture takes precedence over generated web/mobile design suggestions.

Reader and PDF Tools each have a purposeful empty state with a clear local-file action and task-oriented secondary content. Code preview uses a distinct read-only surface, a compact search, line numbers and an explicit copy action. Settings groups Appearance, Voice and Files into bordered, readable surfaces with a slim navigation rail. Keep native document canvases and editing ribbons functional while the common shell sets hierarchy and navigation. Use local state feedback and visible hover/focus targets; do not invent dashboard metrics or decorative fake documents.

Reader media uses a dark video stage with fitted frames, an inline play overlay, a full-width seek track beneath the stage, Previous and Next, 30-second skips, live volume, and a centered transport row. Full-screen video hides the app chrome and keeps a compact transport at the bottom. Pinch zooms a video around the pointer, drag pans it, and Fit restores the whole frame. Audio centers a local abstract record graphic with actual title, artist and album tags when present, filename fallback, and the same seek and volume controls below. Music also supports full screen. A collapsed Up Next pane reveals the local folder queue with name, artist and album sort controls through a compact chevron. The Reader blue anchors the header; coral is reserved for the active play control and progress. The outer surface still follows light/dark appearance. Space toggles playback and arrow keys seek five seconds. These interaction patterns take cues from VLC and YouTube Music while retaining Polymath's own artwork and controls.

Images opened from Finder or Home enter a focused read-only viewer with centered fitted pixels, EXIF orientation, pointer-anchored trackpad pinch zoom and drag-to-pan. A single bottom action strip groups dimensions, one Fit to window command, numeric zoom and full screen. The top-bar Edit in Images action is the deliberate handoff into Lightcraft's editing library. Viewing never imports or alters the source file.

Shared actions, Reader source search, media transport and queue sorting, and Settings motion use the local egui 0.36 port of egui-shadcn controls, mapped to Polymath's semantic colors. Source and Markdown headings open in a narrow, resizable egui_dock outline. Keep its Document pane read-only and use egui_extras tables to virtualize long outlines and media queues. Do not put dock tabs across Home or around the existing editor ribbons.

Reader's landing content uses the available window width, including its recent-file list and drop target. Video keeps the filename in the Reader tab, begins the stage directly below the small context row, and gives the frame the remaining height at the source aspect ratio. Seek, transport, time and volume stay visible beneath it. Avoid a duplicate Now Playing title or codec footer that shrinks the frame.

## Shared chrome contract

Each editor owns its document canvas and task-specific tools. The host bar, navigation, sidebars, tab strips, dialogs, and controls follow one palette: light canvas 250, white raised surface, ink 25, muted ink 102, border 218; dark canvas 22, raised surface 35, ink 240, muted ink 172, border 62. Use the active workspace's existing accent for selection, focus, and primary actions. Keep icon actions at 34 points with an 8-point radius and a visible keyboard focus ring. Toolbars group navigation on the leading side and context actions on the trailing side; move or compact actions before labels clip. Auxiliary sidebars start closed and expose compact directional chevrons with clear hover names. This includes Reader panels, media queue, source outline, Slides thumbnails and Notes, and Images edit tools. The Settings content column stays bounded so opening it never covers the whole document window. Preserve the 125% interface zoom and the narrow sidebar defaults.

Reader images have one Fit to window action, zoom and pan, and a full-screen mode that hides the host bar; double-click enters full screen and Esc exits. Video opens with the queue closed so its stage uses the available Reader width and height. Full screen retains a compact transport. Playlist access stays visible. These patterns follow Apple's [toolbar](https://developer.apple.com/design/human-interface-guidelines/toolbars) and [sidebar](https://developer.apple.com/design/human-interface-guidelines/sidebars) guidance for grouped actions, adaptive width, and discoverable collapse.

Run `python3 tests/native_smoke.py` on the newly bundled application after UI changes. It captures light and dark screenshots for Home, Settings, PDF and office previews, source text, the four document editors, image viewing, and audio/video where FFmpeg is installed, plus image/video full screen. Inspect the resulting `target/native-qa/*.png` in addition to checking command results. The egui native window cannot be driven by browser Playwright; this authenticated local control and screenshot harness exercises the shipped renderer directly.

## Video workspace

A selected clip opens from Reader through Edit video; the original remains untouched. The Video Home card leads to a separate timeline workspace. A dark frame preview sits above a bottom strip timeline with visible trim handles, clip selection, clear reorder actions, audio track controls, export quality presets, and a destination picker. Properties start closed, so the preview has room. Use coral only for selected timeline controls and progress. Exports use the installed local FFmpeg CLI on demand, show phase and progress, support cancellation, and publish a new MP4 without replacing source files.
