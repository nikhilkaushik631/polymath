# Native integration

Polymath is one Rust executable and one eframe/egui window. `Polymath` owns `PdfCraftApp`, `WordApp`, `SheetApp`, `SlideApp` and `LightcraftApp`. Home routes into seven surfaces: Reader and PDF Tools share one `PdfCraftApp`; Writer, Sheets, Slides and Images use their own engines; Video owns a local FFmpeg-backed assembly timeline. Reader has a bounded read-only text viewer for code files and converts supported office files to an in-memory PDF through isolated engine instances. The original file stays untouched; Edit opens it in the corresponding live editor. Markdown and plain text open read-only in Reader, then use Writer when the owner chooses Edit; Writer's Save As dialog offers both formats. Workspace changes preserve all five live editor sessions. The original engines and native file formats remain unchanged.

Each UI library exposes `activate_in_host`, which invalidates context-wide font/theme initialization without clearing documents or undo. Only the active workspace runs its foreground UI. This avoids competing font installations and keyboard handlers. Background autosave and presentation playback are currently tied to the active editor; save before leaving work unattended. Workspace switches themselves do not discard work.

The host handles file routing, macOS open-document/quit Apple events, global shortcuts, close confirmation, common preferences, folder discovery and optional agent transport. Its raw-input hook takes ownership of native close events so an inactive editor's unsaved changes cannot be bypassed. The suite's state is separate from the five standalone applications.

The host enables external document links in the four document editors without changing the standalone editors' copy-only setting. Reader uses its existing link validation and destination prompt; Writer, Sheets and Slides send clicked addresses to the host, which validates web/email schemes and shows the destination before handing it to macOS. The app does not register HTTP or HTTPS schemes. The explicit document-default utility skips HTML so the user's web browser remains the default for links and HTML files.

Writer retains its existing one-document model and confirmation before replacing unsaved work. Reader, Sheets and Slides retain their multiple-document models. Images uses a local, non-destructive Lightcraft library under Polymath's Application Support folder; files imported through Open stay at their original paths. This does not merge file contents or change file fidelity; the existing import/export capabilities and limitations still apply. The app uses the existing local editing engines in one process.

Normal launches create no listening socket. `--control <new-file>` creates a random-port loopback listener with a 256-bit per-launch token. The endpoint file is owner-only and removed by its owning instance on clean exit. Requests are size-bounded and serialized onto the UI thread. Engine tools should inspect before mutating and verify saved output. Local control grants the configured agent the same file access as Polymath; it is not a filesystem sandbox.

Original icons are SVG masters with a generated PNG/ICNS for macOS. Their provenance and hashes are in ATTRIBUTION.md. Native audio, clipboard, printing and picker adapters are retained from the source projects, with their licenses packaged alongside Polymath.

Reader media uses the already-linked `deckcraft-media` crate and the existing `CpalOut` output. File reading and probing run on a worker thread; video frames decode ahead on DeckCraft's worker and upload as egui textures. A separate bounded worker scans sibling files in the opened folder without recursion and reads music tags through the already-linked Symphonia parser. The queue is virtualized in the UI, preserves sorting while changing tracks, and advances when the player reaches the end. Playback is started only on demand and is paused when leaving Reader. Video full screen is a native viewport mode that hides Polymath's top bar until Escape or the exit action. Each file is limited to 512 MB in memory. See [Media](MEDIA.md).

Reader's read-only image viewer uses Lightcraft codecs to produce a bounded, display-encoded sRGB preview on a worker. EXIF orientation is applied before texture upload. Supported camera RAW files use an embedded preview when present. The top-bar Edit action passes the original path to the existing Lightcraft import workflow; viewing alone never adds it to the library.

ZIP, RAR and 7z archives enter Reader tabs. A background worker lists entries with macOS's bundled bsdtar/libarchive; extraction streams selected regular files into a new destination folder after a native folder choice. Unsafe paths, links, glob names and duplicate paths are excluded, and the original archive is never changed. See [Archives](ARCHIVES.md).

Clipboard History runs in the bundled Swift macOS helper, separate from the Rust renderer. It registers the configurable systemwide shortcut with Carbon, polls the pasteboard only while capture is enabled, and displays a native SwiftUI panel. The helper exchanges bounded JSON status and commands with the Rust host over its inherited standard streams; it exits with the host. A bounded local index and image files live under Polymath's Application Support folder with owner-only file permissions. Synthetic pasteboards test capture and pin persistence without exposing a user's clips. See [Clipboard History](CLIPBOARD_HISTORY.md).
